# IS-005 — WORKFLOW.md Parser, Effective Config, and Prompt Rendering

## Status

Frozen.

## File format

`WORKFLOW.md` uses optional YAML front matter plus Markdown prompt body:

```markdown
---
tracker:
  kind: local
---
Prompt body here.
```

If no front matter exists, the whole file is prompt body.

v1 does not allow empty prompt body for dispatch.

## Top-level config keys

```yaml
tracker: {}
polling: {}
workspace: {}
hooks: {}
git: {}
agent: {}
codex: {}
approvals: {}
tools: {}
security: {}
observability: {}
server: {}
ui: {}
prompt: {}
```

Unknown top-level or nested keys generate warnings. Wrong type, missing required field, or unsupported enum generates error.

## Config resolution

Resolution order:

```text
parse front matter
apply v1 defaults
resolve explicit `$VAR_NAME`
normalize paths
coerce and validate
build EffectiveConfig
```

Only full-string `$VAR_NAME` is expanded. No global env override. Config fields do not support Liquid interpolation.

## Path rules

Path fields:

```text
workspace.root
git.repo_root
```

Rules:

```text
~ expands to home
relative paths are relative to WORKFLOW.md directory
normalize to absolute path
no shell commands
no URI
no Liquid template interpolation
```

## Reload

Reload sources:

```text
daemon startup
file watcher
manual API/CLI reload
before-dispatch revalidate
```

Invalid reload preserves last valid effective config. If no last valid config exists, daemon may serve UI/diagnostics but dispatch is blocked.

## Template syntax

Prompt body uses Liquid-style syntax:

```liquid
{{ issue.identifier }}
{{ issue.acceptance_criteria | bullet_list }}
{{ git.branch_name }}
```

Unknown variables and unknown filters fail render.

Supported filters:

```text
default
join
json
bullet_list
indent
truncate
slug
short_hash
markdown_quote
```

No user-defined filters. No filesystem, env, shell, HTTP, random, or current time access from templates.

## Prompt context

Root keys:

```text
issue
attempt
project
workspace
git
run
tools
previous_runs
```

## Final prompt composition

```text
Runtime Envelope
+ Tool Manifest
+ rendered WORKFLOW.md prompt body
+ Context Pack
+ Handoff Contract
```

Runtime Envelope and Tool Manifest are generated by Symphony and cannot be overridden by repo prompt.

## Handoff continuation prompt

If main turn completes with no handoff, v1 sends one continuation prompt. It does not resend the full task prompt.

## Prompt snapshots

Every run saves:

```text
context.json
rendered_prompt.redacted.md
prompt_meta.json
tool_manifest.md
```

DB stores only hashes and artifact paths, not full raw prompt. v1 has no raw prompt export.
