# IS-002 — SQLite Schema v1 and Data Model

## Status

Frozen.

## Database layout

v1 uses two SQLite DBs:

```text
Global App DB: ~/.symphony/app.db
Project DB:    <repo>/.symphony/symphony.db
```

Global App DB stores registered projects, local sessions, and global settings. Project DB stores tracker, run, event, approval, tool, handoff, artifact, review, workflow, and prompt snapshot data.

## v1 non-goal tables

Do not build complete tables for:

```text
audit_log
backup_manifest
migration_history
crash_recovery_leases
supply_chain_findings
```

v1 has only `schema_version` guard for DB compatibility.

## Common conventions

Business IDs are generated by Go as prefixed sortable text IDs:

```text
proj_<id>
iss_<id>
run_<id>
evt_<id>
appr_<id>
tool_<id>
hand_<id>
art_<id>
rev_<id>
wf_<id>
prm_<id>
sess_<id>
```

Issue human identifiers are separate:

```text
LOC-1
LOC-2
```

Time is stored as UTC RFC3339 `TEXT`. Booleans are `INTEGER CHECK (field IN (0,1))`. JSON is stored as `TEXT` and validated in Go.

## Global App DB tables

`registered_projects` contains absolute repo root, project DB path, workflow path, issue prefix, created/updated/last_opened timestamps.

## Key tables and rules

### issues

Stores local tracker facts. Important fields:

```text
id
identifier
sequence_no
title
description
acceptance_criteria_json
state
priority
dispatch_paused
dispatch_pause_reason
created_at
updated_at
completed_at
```

`dispatch_paused` prevents repeated dispatch after failure or missing handoff. G1 adds API/CLI resume.

### issue_relations

A blocks B is represented as:

```text
source_issue_id = A
target_issue_id = B
relation_type = blocks
```

B is ineligible while A is not terminal.

### run_attempts

Statuses:

```text
pending
preparing_workspace
rendering_prompt
starting_agent
running
completed
completed_without_handoff
failed
cancelled
```

v1 stores process IDs for current lifecycle only. No crash recovery leases.

### run_events

`seq INTEGER PRIMARY KEY AUTOINCREMENT` is the SSE replay ID. `id` is a business event ID. UI timelines are rendered from durable `run_events`.

### handoffs and review_packets

Handoff is two-stage:

```text
1. tool writes handoff.
2. finalizer generates review packet.
3. issue enters Human Review only after generated review packet exists.
```

Mark Done requires latest `review_packets.status = generated`.

## Transaction rules

### Create issue

Transaction:

```text
increment issue_sequence
insert issue
insert state_history
insert issue.created event
```

### Transition issue

Transaction:

```text
validate transition
update issue state
insert state_history
insert issue.transitioned event
```

### Dispatch claim

Transaction:

```text
validate active state
validate not paused
validate no active blockers
validate no running run
create run_attempt pending
transition issue to Working if needed
insert scheduler.dispatch_claimed event
```

### Handoff

Tool transaction:

```text
validate run-scoped token
validate running run
insert handoff
insert issue comment
insert tool_call
insert handoff.submitted event
```

Finalizer transaction after review packet files are written:

```text
insert artifacts
insert review_packet generated
run.status = completed
issue.state = Human Review
clear dispatch_paused
insert state_history
insert review.packet_generated event
```

### Missing handoff

After one failed continuation:

```text
run.status = completed_without_handoff
issue.dispatch_paused = true
reason = missing_handoff
system comment
handoff.missing event
```

## Eligibility query

```sql
SELECT i.*
FROM issues i
WHERE i.state IN ('Ready', 'Working', 'Rework')
  AND i.dispatch_paused = 0
  AND NOT EXISTS (
    SELECT 1
    FROM issue_relations r
    JOIN issues blocker ON blocker.id = r.source_issue_id
    WHERE r.target_issue_id = i.id
      AND r.relation_type = 'blocks'
      AND blocker.state NOT IN ('Done', 'Cancelled', 'Duplicate')
  )
ORDER BY i.priority ASC, i.created_at ASC, i.identifier ASC;
```

## PRAGMA

Open DB with:

```sql
PRAGMA foreign_keys = ON;
PRAGMA busy_timeout = 5000;
PRAGMA journal_mode = WAL;
PRAGMA synchronous = NORMAL;
```
