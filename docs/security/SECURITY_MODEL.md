# Security Model — Local Symphony App v1

## Status

Frozen.

## Scope

This document defines v1 security controls from an enforcement perspective. It clarifies which controls are hard-enforced, which depend on Codex approval/sandbox behavior, and which are detection/diagnostic only.

v1 is a local developer tool. It is not a multi-tenant remote service and does not provide compliance-grade audit logging.

## Enforcement matrix

| Control | v1 enforcement source | Bypass risk / limitation | Required tests |
|---|---|---|---|
| Loopback dashboard/API | `serve` host validation, config `require_loopback_api=true`, runtime descriptor uses loopback URL | If operator explicitly disables loopback in future versions, exposure risk changes. v1 remote dashboard unsupported. | non-loopback bind rejected when required |
| Browser session | HttpOnly SameSite=Lax cookie, session token hash in app DB, expiry/revocation check | Local malware/browser compromise is out of scope. | invalid/expired/revoked session rejected |
| CSRF | CSRF header required for cookie-authenticated command APIs | Read-only GET endpoints do not require CSRF. | command without `X-Symphony-CSRF` rejected |
| CLI auth | Bearer token in local CLI session file, hash stored in app DB | File-system user compromise is out of scope. | wrong/expired token rejected |
| Open token | one-time token generated by `symphony open`, short TTL, consumed by `/auth/exchange` | Token in browser URL may appear in local browser history during TTL. | token reuse rejected |
| Tool token | run-scoped bearer token, hash stored in project DB, expiry/revocation, run/issue/tool/cwd scope | If a command can read environment variables inside the workspace process, token disclosure within the same run is possible. Token scope limits blast radius. | wrong run/issue/cwd/tool rejected |
| Workspace cwd | daemon validates Codex launch cwd and Tool Gateway validates cwd-under-workspace | Shell commands may use absolute paths unless Codex sandbox/approval catches them. | attach and tool calls reject outside workspace |
| Command policy | Codex approval request bridge plus adapter policy classification | Hard enforcement depends on Codex surfacing shell command approval requests before execution. If Codex executes without approval, daemon can only detect through events/artifacts. | fake command approval/deny tests |
| Network policy | Codex network approval bridge when protocol surfaces network requests | v1 has no OS firewall or packet-level egress blocking. If Codex/tooling bypasses approval, daemon cannot guarantee hard network deny. | fake network request denied |
| Protected path read | path policy on file approval/tool/artifact surfaces | Shell commands using absolute paths require Codex approval/sandbox to enforce before execution. | `.env` / `.ssh/**` read approval/deny tests |
| Protected path write | path policy denies file-change approvals and artifact writes to protected paths | Hard enforcement depends on Codex surfacing write/file-change approval before write. No OS-level file sandbox is specified in v1. | `.env`, `.npmrc`, key-file write denied |
| Artifact containment | daemon-controlled path resolution under `.symphony/artifacts` or `.symphony/exports` | This is hard-enforced by daemon API/tool path validation. | path traversal and absolute path rejected |
| Redaction | daemon redacts event/tool/prompt/review/diagnostic surfaces before persistence or exposure where specified | Redaction is best effort; raw workspace files are not redacted. | golden redaction fixtures |
| Raw logs | API refuses raw prompt/raw Codex log export in v1 | Raw files may exist locally for diagnostics depending on implementation; API must not expose them. | raw log content endpoint rejected |

## Auth token requirements

### Session and CLI tokens

- Generate at least 128 bits of entropy; 256 bits is preferred.
- Store only SHA-256 or stronger hashes in DB.
- Use constant-time comparison for presented token hash checks.
- Browser cookie name: `symphony_session`.
- CSRF header name: `X-Symphony-CSRF`.
- Cookie attributes: `HttpOnly`, `SameSite=Lax`, `Path=/`; `Secure` when served over HTTPS.
- CLI token file should be readable only by the current user where the OS supports file modes.

### Open tokens

- One-time use.
- Short TTL; recommended maximum 5 minutes.
- Stored as hash only.
- Consumed by `POST /api/v1/auth/exchange`.
- Reuse after successful exchange returns `unauthorized`.

### Tool tokens

- One token per run.
- Store only token hash.
- Scope includes project_id, issue_id, run_id, workspace_path, allowed_tools, and expires_at.
- Revoke on run terminal outcome, operator cancel, approval `cancel_run`, reconciliation cancel, and daemon shutdown.
- Tool token expiry must not exceed the run timeout plus small cleanup grace.

## Command policy detail

Default allow commands are low-risk local inspection/test commands plus fixed `symphony tool ...` gateway commands. `symphony tool ...` allow does not grant authority by itself; the daemon validates token, run, issue, cwd, schema, and registry.

Default review commands require approval. Default deny commands should be denied without asking unless config explicitly overrides in a future version.

If denial terminates the run, map to canonical failure codes:

```text
command_denied
network_denied
protected_path_denied
```

## Network policy detail

Default network policy is deny. v1 does not include an OS firewall. Enforcement depends on Codex app-server surfacing network requests through the approval protocol or a future sandbox layer.

Documentation and UI must not describe v1 network denial as packet-level isolation.

## Protected path defaults

Protected path patterns:

```text
.env
.env.*
**/*.pem
**/*.key
**/*_rsa
**/*_ed25519
.ssh/**
.aws/**
.gcp/**
.azure/**
.kube/**
.npmrc
.pypirc
.netrc
```

Rules:

```text
write protected path → deny
artifact attach protected path → deny
read protected path → deny or approval according to policy mode; default is deny for known secret patterns
```

## Artifact and export paths

All served artifact paths must resolve under:

```text
<repo>/.symphony/artifacts
<repo>/.symphony/exports
```

Reject:

```text
absolute path input
path traversal
symlink escape
protected path attachment
raw prompt content request
raw Codex log content request
```

## Diagnostics export

Diagnostics export is redacted-only in v1.

`include_raw_logs=true` must return `raw_log_access_not_supported`.

## Security regression suite

Required tests:

```text
loopback required bind validation
browser session invalid/expired/revoked
CSRF missing on command API
CLI bearer invalid/expired
open token one-time use
tool token wrong run/issue/cwd/tool/expired/revoked
command allow/review/deny classifications
network denied fake request
protected path read/write/attach denied
artifact path traversal and symlink escape
redaction golden fixtures
raw prompt/raw Codex log API refusal
```
